# فرهنگ داده — گزارش ظرفیت داروخانه (سازمان غذا و دارو)

هر ردیف سرویس `GetVaziatShowShahrestanAndOStanQueryAsync` یک آبادی (شهر یا روستا) را
توصیف می‌کند. جدول‌های مقصد در `data/pharmacy.sqlite`:

| جدول | دانه‌بندی | توضیح |
|---|---|---|
| `raw_rows` | یک ردیف به‌ازای هر رکورد API | رکورد خام JSON + هش یکتا + صفحهٔ مأخذ + زمان بارگذاری |
| `cities` | `ShahrID` | نام، نوع (شهر/روستا)، استان، شهرستان، بخش، دانشگاه اصلی |
| `city_stats` | `ShahrID` | همهٔ سنجه‌های عددی (یکتا برای هر شهر) |
| `city_universities` | `ShahrID`×`OrganizationID` | نگاشت چند-به-چند شهر↔دانشگاه |
| `provinces` / `counties` / `districts` / `universities` | شناسه | جدول‌های مرجع نام‌ها |
| `v_city` | `ShahrID` | نمای تخت برای اپ: نام‌های جغرافیایی + سنجه‌ها + نسبت‌های مشتق |

## مدل فروش بدون نسخه (OTC) — ساختهٔ اپ

داروخانه دو بازار دارد: نسخهٔ بیمه‌ای (سهم بیمه، حاشیهٔ regulated) و سبد آزاد
(آرایشی، بهداشتی، مکمل، داروهای OTC). بازار دوم به **جمعیت** وابسته نیست، به
**توان خرید** وابسته است — دو آبادی هم‌جمعیت می‌توانند دو بازار کاملاً متفاوت
داشته باشند. نمای `v_place_prosperity` فقط ورودی‌های اندازه‌گیری‌شده را می‌دهد و
مدل در `web/src/lib/otc.ts` پیاده شده است.

| ستون | معنا | منبع |
|---|---|---|
| `county_urban_share` | سهم جمعیت شهرستان که در شهر / آبادی ≥ ۱۰٬۰۰۰ نفر / آبادی دارای ≥ ۳ داروخانه زندگی می‌کند | محاسبه از خود داده (ردیف‌های `pop_outlier` کنار گذاشته می‌شوند) |
| `hh_size` | بُعد خانوار = جمعیت مرجع ÷ خانوار سرشماری | `population_reference` (اگر بارگذاری شده باشد؛ وگرنه `NULL` = «بی‌اطلاع»، نه میانگین) |

نمای `v_otc_anchors` لنگر رسمی مدل را از سالنامهٔ استان می‌دهد:

| ستون | معنا |
|---|---|
| `urban_hh_expenditure` / `rural_hh_expenditure` | هزینهٔ خالص سالانهٔ خانوار شهری/روستایی، سالنامه ۱۴۰۳ (هزار ریال) |
| `rural_to_urban_ratio` | نسبت اندازه‌گیری‌شدهٔ روستا به شهر (~۰٫۶) — همین عدد ضریب روستا در مدل است |
| `urban_consumption_per_capita` / `rural_consumption_per_capita` | همان هزینه‌ها تقسیم بر بُعد خانوار |
| `urban_hh_size` / `rural_hh_size` | بُعد خانوار از سرشماری ۱۳۹۵ برای کل استان |

فرمول‌ها (`lib/otc.ts`):
`power = urbanity × county_urban × household × agglomeration`، نرمال‌شده بر
میانگین وزنی جمعیت (پس `1.0` = میانگین کشور)؛ `فروش سرانه = پایه × power^کشش`;
`بازار آبادی = جمعیت × فروش سرانه`؛ سهم داروخانهٔ تازه = `بازار ÷ (n + ۱)`.

## هشدارهای تفسیری

1. ردیف‌های تکراری یک شهر در دادهٔ خام، رکورد یکسان‌اند و فقط دانشگاهشان فرق می‌کند؛ برای شمارش
   «چند داروخانه در کشور» هرگز ردیف‌ها را جمع نزنید — از `cities`/`city_stats` استفاده کنید.
2. سه ردیف با نام جای‌گیر (`**`، `-`) در منبع وجود دارد که جمعیت کامل یک شهر بزرگ را حمل می‌کند
   (مثلاً `**` در شهرستان سنندج با ۹۰۰٬۰۰۰ نفر). ستون `cities.name_junk` این‌ها را نشانه می‌زند و
   تحلیل به‌صورت پیش‌فرض کنارشان می‌گذارد.
3. چهار ردیف جمعیتشان عیناً با آبادی دیگری یکسان است (انتساب جمعیت شهر مادر به آبادی همسایه —
   تهران بزرگ/شهر تجريش، شهر گلستان/شهر گلستان). ستون `city_stats.pop_shared_big` (تعداد
   `ShahrID`هایی که این مقدار جمعیت را دارند) و نمای `v_city.pop_ambiguous` این وضعیت را افشا می‌کند.
4. جمعیت‌ها از منبع سامانه‌اند و ممکن است با سرشماری رسمی متفاوت باشند؛ سال مبنا در داده نیست.
5. ستون‌های `ZarfiatKhali*` در کل کشور صفر/تهی‌اند ⇒ در اپ با «ظرفیت خالی تخمینی» جایگزین شده‌اند
   که یک فرض برنامه‌ریزی است، نه عدد رسمی سازمان.
6. `HadaghaleEmtiaz` آستانهٔ *امتیاز متقاضی* است، نه معیار جمعیتی — برای هر شهر باید با
   امتیاز خود متقاضی سنجیده شود.
7. اپ هیچ ادعایی دربارهٔ «مجوز قطعی» ندارد؛ مرجع نهایی، سامانهٔ سازمان و کارشناسی دانشگاه است.

## لایهٔ نقشه (ساختهٔ `etl/build_map_layer.py`)

نقشهٔ تعاملی `‎/map` از این جدول‌ها می‌خواند. جمعیت و تعداد داروخانه **کپی
نمی‌شوند**: `v_map_settlement` همان `v_admin_area_current` را با شمارش زندهٔ فید
سازمان جوین می‌کند. فقط چیزهایی که با یک کوئری محاسبه‌شدنی نیستند (فاصله روی
گراف و شبکهٔ تراکم) ذخیره می‌شوند.

| جدول / نما | دانه‌بندی | معنا |
|---|---|---|
| `map_point` | هر سکونتگاه نقشه‌دار | مختصات، خط مستقیم، فاصلهٔ جاده‌ای (اگر OSRM اندازه گرفته باشد)، فاصلهٔ گراف، حلقه، تعداد گام |
| `map_edge` | جفت بی‌جهت | درخت پوشای کمینه‌ای که نقشه رسم می‌کند (n−1 یال) |
| `map_density` | سلول شبکهٔ مسکونی | جمعیت و داروخانهٔ درون ۱۰ کیلومتر، تراکم در ۱۰٬۰۰۰ نفر، شکاف |
| `map_import` | یک ردیف | پارامترها، ضریب کالیبراسیون، شمارش‌ها، زمان ساخت |
| `v_map_settlement` | هر سکونتگاه | ردیف اداری + شمارش زندهٔ داروخانه + فاصله‌ها |

| ستون | معنا |
|---|---|
| `straight_km` | فاصلهٔ خط مستقیم از اهواز |
| `road_km` / `road_minutes` | فاصله و زمان رانندگی OSRM (اندازه‌گیری‌شده، ۶۳۵ نقطه) |
| `net_km` | دایجسترا روی گراف همسایگی سکونتگاه‌ها؛ کران پایین جاده |
| `est_km` | عددی که رابط کاربری نشان می‌دهد |
| `dist_source` | `road` \| `network` \| `straight` \| `reference` — منبع همان عدد |
| `ring_km` | لبهٔ پایین بازهٔ فاصله (۰، ۲۵، ۵۰، ۷۵، ۱۰۰، ۱۵۰، ۲۰۰، ۳۰۰) |
| `deg` | تعداد گام گراف از اهواز (نزدیکی شبکه‌ای، نه کیلومتر) |
| `map_density.dens` | داروخانه در ۱۰٬۰۰۰ نفر، در پنجرهٔ ۱۰ کیلومتری همان سلول |
| `map_density.gap` | جمعیت ÷ ۵٬۴۰۸ منهای داروخانه؛ مثبت = کمبود |

سلولی ساخته می‌شود که سکونتگاهی در ۲٫۵ کیلومتری آن باشد؛ بنابراین بیابان، هور و
ارتفاعات هیچ سلولی ندارند و لایهٔ رنگ هرگز روی زمین خالی نمی‌افتد.
